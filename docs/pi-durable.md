# pi-durable: what it is and whether to build 24/7 agents on it

Researched 2026-10-09 against `@earendil-works/pi-durable@1.1.0` (tag [`v1.1.0`](https://github.com/earendil-works/pi/tree/v1.1.0), commit `abe508e`), with `main` at `42a3497` for unreleased changes. Links of the form `durable/README.md#L..` point into that tag. `D` = `https://github.com/earendil-works/pi/blob/v1.1.0/packages/durable`.

## TL;DR

pi-durable is a TypeScript **library**, not a daemon or a CLI. It is an agent harness from the pi monorepo that commits every transcript entry, model turn, tool call and piece of your own state to storage (SQLite, JSONL, memory, or a Cloudflare Durable Object) before showing it. A process that dies mid-turn resumes from its last checkpoint when it reopens the storage. It is MIT-licensed, maintained by Mario Zechner (badlogic) and Armin Ronacher (mitsuhiko), at 1.1.0, and marked **Experimental: the API changes without notice**. Patch releases have shipped breaking changes. It does **not** run the interactive `pi` CLI, its extensions (`pi.on`, `registerTool`) or herdr's integration. To use it you write your own host process, with its own extension API. AGENTS.md and skills only work if your host renders them (the experimental durable TUI and Pi Pocket both do). Remote access (`pi-server` / `pi-client` / `pi-protocol`) is an unauthenticated Unix-socket building block. It is not a product you can point at Tailscale. **Verdict:** keep interactive pi in herdr as it is. On the Linux box, use pi-durable for *specific headless agents you write* (bots, schedulers, triage loops), under systemd with SQLite storage. Try **Pi Pocket in `--access tailscale` mode** first as a zero-code way to see whether durable, always-on sessions are worth it.

## 1. What it is

**Purpose.** Earendil describes pi-durable as "an experimental framework … for building long-running, durable, and modifiable agents that can run in many environments". It is a harness for "any agentic application, coding agents included". It explicitly does not replace the coding agent ([earendil.com/posts/pi-durable](https://earendil.com/posts/pi-durable/), 2026-10-01). The npm description is "Durable conversation, task, and document runtime for Pi" ([npm](https://www.npmjs.com/package/@earendil-works/pi-durable)).

**Core concepts** ([`D/README.md#L78-L99`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/durable/README.md#L78-L99)):

| Concept | Meaning |
|---|---|
| Harness / Session | One open storage plus the machinery that runs agents on it. All changes go through one line of atomic commits. |
| Conversation | A transcript of immutable entries (`pi.user`, `pi.assistant`, `pi.tool-result`, `pi.system`, `pi.reset`, your own kinds). Conversations can be forked or owned by a task, as subagents are. |
| Document | Typed JSON state committed with entries. Built-ins: `pi.agent`, `pi.provider`, `pi.live`, `pi.inbox`, `pi.usage`. |
| Task | A durable state machine that checkpoints every step. `pi.generation` calls the model and owns one `pi.tool` task per tool call. |
| Submission | Input or a write handed to a conversation. It can be waited on and is idempotent by `requestId` ([`#L115-L124`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/durable/README.md#L115-L124)). |
| Extension / Registry | Named bundles of tools, prompt sections, hooks, wrappers and tasks, installed in memory by your process. Conversations store only the names ([`#L126-L145`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/durable/README.md#L126-L145)). |

**What "durable" concretely guarantees.** These come from the normative spec ([`D/docs/spec.md#L40-L78`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/durable/docs/spec.md#L40-L78)):

- Commits are atomic across entries, tasks and documents. Only committed state is observable, and "there is no volatile publication path".
- External effects (model, tool, process, network) run *outside* the transaction, in an "effect sandwich": commit intent, perform the effect, commit the outcome ([`spec.md#L1872-L1888`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/durable/docs/spec.md#L1872-L1888)).
- After a crash, `harness.resume()` continues pending work ([`README#L103-L113`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/durable/README.md#L103-L113)). An interrupted tool call reruns only if it is declared `replay: "safe"`. Otherwise the model gets an `interrupted` error result with the output committed so far ([`README#L168`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/durable/README.md#L168)). The default is `unsafe` ([`D/src/harness/types.ts#L217`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/durable/src/harness/types.ts#L217)). The built-in `read`/`write`/`edit`/`bash` tools declare no replay policy, and a request to change that was closed as not planned ([#10320](https://github.com/earendil-works/pi/issues/10320)). So a crash mid-`bash` means "interrupted", not "re-run".
- Streamed partials and tool output are committed at most every 100 ms by default, so a crash loses at most that window ([`README#L304`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/durable/README.md#L304)).
- On power loss, SQLite runs in WAL mode with `synchronous = NORMAL`. Commits survive process crashes, but "the newest may be lost on power or host failure". JSONL can `fsync` each commit ([`README#L538-L543`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/durable/README.md#L538-L543), [`D/src/storage/sqlite/node.ts#L190-L191`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/durable/src/storage/sqlite/node.ts#L190-L191)).

## 2. How it runs

- **Library only.** The package has no `bin`. You `Harness.open(storage, { models, registry, env }, context)` inside your own Node (>= 22.19) process ([npm `package.json`](https://www.npmjs.com/package/@earendil-works/pi-durable?activeTab=code), [`README#L44-L76`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/durable/README.md#L44-L76)). Any supervision (systemd, launchd, k8s) is yours to set up.
- **Process model.** It is single-writer: "One process owns a storage at a time; there is no cross-process locking" ([`README#L545`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/durable/README.md#L545)). badlogic confirmed that a second process writing the same DB "can not work, as it violates the single writer invariant" ([#10659](https://github.com/earendil-works/pi/issues/10659)). A multi-writer fencing proposal was closed as not planned ([#10534](https://github.com/earendil-works/pi/issues/10534)). Tools run through a pluggable `ExecutionEnv` (`NodeExecutionEnv` locally, [`README#L235-L262`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/durable/README.md#L235-L262)). The sibling package `@earendil-works/pi-env` adds a Rust daemon, deployed over SSH, so tools run on another machine while the harness, storage and credentials stay local ([`packages/env/README.md`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/env/README.md)).
- **Storage backends:** Memory, SQLite (Node's built-in `node:sqlite`), JSONL, and a Cloudflare Durable Object's SQLite (added in 1.1.0) ([`README#L536-L545`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/durable/README.md#L536-L545), [`D/CHANGELOG.md`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/durable/CHANGELOG.md)). `@byok-sdk/cloud-do` is a **third-party** Durable Object host by `ancienttwo`, not an Earendil package ([npm](https://www.npmjs.com/package/@byok-sdk/cloud-do)).
- **Remote access.** `pi-protocol` defines 4-byte length-prefixed CBOR frames carrying routed envelopes `{serverId, sessionId, attachmentId}`. It "is experimental and has no compatibility guarantees" ([`packages/protocol/README.md#L41`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/protocol/README.md#L41)). `pi-server` is an "Experimental local server that routes clients to application-hosted durable Sessions". The only transport is a Unix socket (mode `0600`) ([`packages/server/README.md#L3`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/server/README.md#L3), [`listener.ts#L11`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/server/src/transports/unix/listener.ts#L11)). `pi-client` "never reconnects or replays requests automatically" ([`packages/client/README.md#L34`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/client/README.md#L34)). Neither `pi-server` nor `pi-client` depends on pi-durable; the application wires them together ([`server/package.json`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/server/package.json)).
- **Auth.** There is none. "Peer authentication and authenticated service contexts are not implemented" ([`protocol/README.md#L39`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/protocol/README.md#L39), [`server/README.md#L61`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/server/README.md#L61)). Over Tailscale you would rely on the tailnet, plus your own transport and auth. Model credentials come from pi-ai. The experimental agent and Pi Pocket reuse pi's `~/.pi/agent/auth.json` ([experimental `durable/README.md`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/coding-agent/src/experimental/durable/README.md), [Pi Pocket `customizing.md`](https://github.com/TannerMidd/pi-pocket/blob/d01f763b02f06ff6144d4366eb966a76dbb35577/docs/customizing.md)).
- **Watching a running agent.** All UI state is committed state. `conversation.viewState()` / `watch()` stream exact operations per commit, and `watchEvents()` gives coding-agent-style events. Late joiners start from the current view; nothing is replayed. A slow watcher holding more than 100 frames gets one full snapshot instead ([`README#L276-L302`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/durable/README.md#L276-L302), [`#L368-L382`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/durable/README.md#L368-L382)). Several clients can attach and steer ([Earendil post](https://earendil.com/posts/pi-durable/)). A human "attaches" through whatever UI the host builds (TUI, web, chat bot). There is no generic attach command.

## 3. Relation to the interactive `pi` CLI, extensions, skills and AGENTS.md

- **The CLI does not use it.** `@earendil-works/pi-coding-agent@1.1.0` (what you run, `pi --version` = 1.1.0) does not depend on pi-durable ([`coding-agent/package.json`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/coding-agent/package.json)). The CLI keeps its own session model from pi-agent-core ([`coding-agent/CHANGELOG.md`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/coding-agent/CHANGELOG.md), 0.84.0 entries). Earendil says lessons "will flow back into Pi the coding agent as they prove themselves valuable" and gives no migration plan ([post](https://earendil.com/posts/pi-durable/)).
- **Your extensions cannot run in it.** pi-durable extensions are `defineExtension({ tools, sections, hooks, wraps, tasks })`, a different API from the CLI's `ExtensionAPI`. An open issue asks for coding-agent extension hosting and lists the hook gaps: compaction mutation, `message_end` replacement, `setActiveTools` loadouts, synchronous `SessionManager` ids ([#10386](https://github.com/earendil-works/pi/issues/10386), open, no maintainer reply). So `herdr-agent-state.ts`, `moshi-*`, `gentle-engram`, `pi-subagents`, `pi-intercom` and the rest of `pi/settings.json` `packages` would each need porting.
- **AGENTS.md and skills are a host concern.** pi-durable ships none of them. The spec's examples have the host define `ContextFiles` and `Skills` extensions with its own `renderAgentsMd` / `renderSkills` ([`spec.md#L2452-L2453`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/durable/docs/spec.md#L2452-L2453)). The experimental durable agent in the pi repo does this by reusing the CLI's loaders, so AGENTS.md and skills from `~/.pi/agent` work there ([`experimental/durable/prompt.ts#L20-L34`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/coding-agent/src/experimental/durable/prompt.ts#L20-L34)). Pi Pocket does the same ([`customizing.md`](https://github.com/TannerMidd/pi-pocket/blob/d01f763b02f06ff6144d4366eb966a76dbb35577/docs/customizing.md)). Because `~/.pi/agent` symlinks to `dotfiles/pi`, either host would pick up your AGENTS.md, skills, prompts and auth unchanged. **Unverified**: not tested here.
- **Experimental durable TUI.** `packages/coding-agent/src/experimental/durable/` is "A small local coding agent on pi-durable" with SQLite under `~/.pi/agent/experimental/durable-sessions/…`, `--continue`, subagents and a task panel. It lists as "Not here: sessions list and resume picker, forks and tree navigation, extensions, prompt templates, images, `/login`" ([README](https://github.com/earendil-works/pi/blob/v1.1.0/packages/coding-agent/src/experimental/durable/README.md)). This code, and the experimental `pi server` / `pi client` (`PI_EXPERIMENTAL=1`), "are excluded from npm packages and standalone binaries" ([`experimental/services/README.md#L12`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/coding-agent/src/experimental/services/README.md#L12)). The npm tarball's `files` excludes `dist/experimental`, which I checked in the 1.1.0 tarball. You only get it from a source checkout, or bundled by entwurf (section 5).
- **Migration story: none.** Moving means rewriting each extension against `defineExtension` / hooks, and accepting the gaps in #10386. Sessions do not convert: the CLI's JSONL sessions and pi-durable storage are separate formats (see the CLI's [`session-format.md`](https://github.com/earendil-works/pi/blob/v1.1.0/packages/coding-agent/docs/session-format.md) and the storage section above).

## 6. Fit verdict for 24/7 agents on the home Linux server

**Not as a replacement for your pi + herdr setup. Yes as the base for specific, self-written always-on agents. Start with Pi Pocket to find out whether you want them.**

Why not as the general base:

- Your daily value lives in CLI extensions (herdr state and attention, moshi alerts, engram, pi-subagents, intercom, auto-model). None of them loads in pi-durable (#10386).
- herdr cannot see a pi-durable session as an agent today. Its pi integration is a CLI extension (`pi/extensions/herdr-agent-state.ts`), and the only herdr–pi-durable bridge so far declines to claim support (entwurf, above). You could write a durable hook extension that reports to herdr's socket, but that is new work, and **unverified** as feasible.
- The API breaks in patch releases, so any host you write must pin exact versions and expect churn.

What pi-durable is good at, for this box:

- Headless loops that must survive restarts: a CI-failure triage agent, a scheduled "summarize overnight CI" job, a chat-bot front end. One process owns one SQLite file. Recovery is real: `resume()` plus `requestId` gives idempotent submissions. An unclean shutdown costs at most the 100 ms progress window, plus the newest commit on power loss. A UPS is worth having for an always-on box regardless.
- 32 GB RAM is not a constraint. Only the working set stays in memory ([post](https://earendil.com/posts/pi-durable/)). The RTX 2070 Super is irrelevant unless you also run local models, since pi-durable calls providers through pi-ai.

**Concrete plan, in order:**

1. **Try Pi Pocket first (an evening, no code).** On the Linux server: install Node ≥ 22.19 and pi, check out `dotfiles` so `~/.pi/agent` → `dotfiles/pi`, run `pi` → `/login`, then `npm start` in a pinned Pi Pocket checkout with `--access tailscale`. Run it under a systemd user service; Pi Pocket supports running without a terminal via `--access` ([README](https://github.com/TannerMidd/pi-pocket/blob/d01f763b02f06ff6144d4366eb966a76dbb35577/README.md#configuration)). Use it from the MacBook and phone for a week: schedules, `/until`, steering mid-run, a server restart mid-turn. Keep it tailnet-only and single-user, because anyone who can steer runs commands as you.
2. **If you want custom 24/7 agents, write a small host** modelled on `pi-durable-substrate`'s `server.ts`: `openNodeSqliteStorage`, `CodingTools`, `resume()`, close on SIGTERM. Add an AGENTS.md/skills section the way `experimental/durable/prompt.ts` does, and listen only on the Tailscale IP behind your own token, since the pi protocol has no auth. Declare idempotent tools `replay: "safe"`, give every external trigger a stable `requestId`, and run one systemd unit per storage file with `Restart=always`. Pin `@earendil-works/pi-durable`, `pi-ai` and `chord` to exact versions. If tools should act on the Mac mini (Xcode signing), look at `@earendil-works/pi-env` for remote execution over SSH rather than running the harness there.
3. **Keep interactive work as is.** Run pi in herdr panes on the Mac mini or the Linux box via herdr's SSH machines. If you only need crash-safe subagents inside the CLI, `pi-durable-subagents` is the lower-friction option because it keeps your extensions. It does not use pi-durable, and is **unverified** with your pi-subagents setup.
4. **Re-check when** #10386 (extension hosting) gets a maintainer answer, the CLI starts depending on pi-durable, or `pi server` / `pi client` ship in the npm package. Any of those changes the verdict.
